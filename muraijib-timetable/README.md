# Muraijib Smart Timetable
**منظومة مريجب الذكية لإدارة الجدول المدرسي** · العام الأكاديمي 2026–2027

منصة داخلية لنائب مدير المدرسة: تبني الجدول، وتحرسه بمحرك قيود، وتساعد على التعامل مع
تغيّرات العام الدراسي خلال دقائق بدل ساعات من العمل اليدوي.

---

## السؤال الذي بُني عليه كل قرار

> هل تجعل هذه الميزة نائب المدير قادرًا على التعامل مع تغيير مفاجئ في الجدول خلال دقائق؟

الأولوية: **الدقة ← السرعة ← التحكم ← القابلية للتفسير ← التصميم المهني**.

---

## التشغيل

```bash
cd muraijib-timetable
npm install
cp .env.example .env.local     # NEXT_PUBLIC_DATA_MODE=local
npm run dev                    # http://localhost:3000
```

يبدأ النظام ببيانات تجريبية واضحة التعليم (أسماء رقمية: «معلمة 1») مع شريط تنبيه دائم
لا يمكن إخفاؤه، إلى أن تُستورد بيانات المدرسة من **استيراد البيانات**.

```bash
npm test        # 63 اختبارًا لمحرك القيود والمساعد والاستيراد
npm run build   # بناء الإنتاج
npm run typecheck
```

## ما الذي يميّز هذه المنظومة

### 1. المحرك يقرر، لا النموذج اللغوي

قرارات الجدولة تُتخذ بمحرك قيود حتمي (`lib/engine/`) مكتوب بدوال صافية.
المساعد الذكي يخطط ويشرح ويستدعي **أدوات للقراءة والمحاكاة فقط** — لا يملك صلاحية الكتابة إطلاقًا.
سبب هذا الاختيار: قرارات الجدول يجب أن تكون قابلة للتكرار والتفسير والمساءلة.

### 2. ثلاث طبقات دفاع ضد الحجز المزدوج

| الطبقة | الغرض |
|---|---|
| الواجهة | معاينة فورية أثناء السحب — للسرعة |
| المحرك | تحقق كامل من 11 قيدًا صارمًا قبل بناء أي مقترح |
| قاعدة البيانات | فهارس فريدة تجعل الحجز المزدوج **مستحيلًا** فيزيائيًا |

الطبقة الثالثة متحقَّق منها فعليًا على PostgreSQL 16 — انظر `supabase/README.md`.

### 3. لا كتابة بلا معاينة

```
طلب → تحليل → تحقق من القيود → قياس الأثر → معاينة → موافقة → تطبيق → نسخة جديدة → تدقيق
```

كل تغيير — من السحب أو من المساعد أو من الاستيراد — يُمثَّل بالشكل نفسه (`ChangeSet`)
ويمرّ بالبوابة نفسها. زران فقط في نهاية المعاينة: **اعتماد التغييرات** · **إلغاء**.

### 4. أقل تغيير ممكن

عند تغيّر خلال العام لا يُعاد بناء الجدول. تُحدَّد الحصص المتضررة، ويُجمَّد كل ما عداها،
ويُبحث عن حل بعمق متزايد. يُعرض دائمًا **عدد الحصص التي ستتغيّر**.

### 5. لا رقم بلا تفسير

درجة جودة الجدول تُعرض دائمًا مفصَّلة بندًا بندًا: كم نقطة فُقدت في كل بند ولماذا.
وأي انتهاك صارم مانع يجعل الدرجة **صفرًا** — لا معنى لجدول أنيق التوزيع وفيه معلمة في مكانين.

### 6. لا حل مخترع

إن عجزت الطاقة المتاحة عن استيعاب الحصص، يقول النظام ذلك صراحةً ويحدّد كم حصة تحتاج
معلمة بديلة — بدل عرض حل جزئي وكأنه كافٍ.

## استيراد بيانات المدرسة

```
رفع الملف ← مطابقة الأعمدة ← تقرير تدقيق ← معاينة ← اعتماد كـ Baseline v1.0
```

الصيغة المتوقعة: **صف واحد لكل حصة** (اليوم · الحصة · الشعبة · المادة · المعلمة)،
وقالب جاهز للتنزيل من داخل المعالج. تُستخرج المعلمات والمواد والصفوف والشعب وخطة المواد
من الملف نفسه.

لا يُستورد صف خاطئ بصمت: كل صف مرفوض يُذكر برقمه وسببه، ويُعرض التقرير كاملًا قبل أي كتابة.

## الهوية البصرية

**لم تُخترع ألوان وزارية ولم يُعَد رسم أي شعار.** الألوان كلها في `app/tokens.css`
كمتغيرات CSS، والشعار مكانه محجوز في الترويسة بإطار واضح.

عند تزويد المشروع بالأصول الرسمية:
1. ضع الملفات في `public/brand/`
2. حدّث المسارات في `lib/brand.ts`
3. حدّث القيم في `app/tokens.css`

لا حاجة لتعديل أي مكوّن — لا يوجد لون ثابت داخل الكود.

|---|---|
| 1 — الأساس: المحرك، البيانات، Design System، المعلمات/الصفوف/المواد/الأنصبة | ✅ |
| 2 — نواة الجدول: 7 طرق عرض، القيود، كشف التعارض، القفل | ✅ |
| 3 — التغيير الديناميكي: سحب وإفلات، معاينة، نسخ، تدقيق، أقل تغيير | ✅ |
| 4 — المساعد الذكي: أوامر عربية، تحليل أثر، محاكاة، بدائل، موافقة | ✅ |
| 5 — الطباعة والتحليلات: 7 مطبوعات، تصدير، 9 مؤشرات، فحص صحة | ✅ |
| قاعدة البيانات: المخطط + RLS + الاعتماد الذرّي | ✅ متحقَّق منه على PostgreSQL 16 |

### ما لم يُنفَّذ بعد — بوضوح

- **ربط وضع الإنتاج:** المخطط جاهز ومتحقَّق منه، لكن مسارات `/api` وعميل Supabase لم تُنفَّذ.
  تشغيل `NEXT_PUBLIC_DATA_MODE=supabase` يفشل برسالة صريحة بدل أن يعمل نصف ربط.
  الوضع المحلي (IndexedDB) يعمل بالكامل بالقيود نفسها والنسخ والتدقيق.
- **تصدير PNG:** غير منفَّذ. التصدير المتاح: طباعة/PDF عبر المتصفح، وExcel، وCSV.
- **قراءة الجداول بصيغة الشبكة تلقائيًا:** المعالج يقرأ الصيغة الطولية فقط،
  ويوفّر قالبًا للتحويل.

## ملاحظة أمنية: مكتبة قراءة ملفات Excel

النسخة المتاحة من `xlsx` على npm هي **0.18.5**، وعليها تنبيهان أمنيان معلنان بلا إصدار
إصلاحي على npm: تلويث النموذج الأولي (GHSA-4r6h-8v6p-xvw6) وبطء تنظيمي (GHSA-5pgg-2g8v-p4x9).
المنظومة تقرأ ملفات يرفعها المستخدم، فهذه ليست ملاحظة نظرية.

**ما جرى بشأنها في هذه النسخة:**

1. **القراءة تتم دائمًا بـ `{ header: 1 }`** فتعود مصفوفات لا كائنات، فلا يتحوّل أي عنوان
   عمود قادم من الملف إلى مفتاح كائن. هذا يغلق مسار تلويث النموذج الأولي عمليًا.
   القرار **مُختبَر ومحروس** في `tests/import-safety.test.ts` حتى لا يُلغى لاحقًا بحسن نية.
2. **كل القراءة تتم في المتصفح**، لا على الخادم: أسوأ أثر متبقٍّ لمسار البطء التنظيمي
   هو تعليق تبويب المستخدم على ملف اختاره بنفسه — لا أثر على الخادم أو على مستخدم آخر.

**الإصلاح الكامل الموصى به من المطوّر:**

```bash
npm install "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"
```

النسخة 0.20.3 تعالج التنبيهين، وهي تُوزَّع من موقع SheetJS لا من npm. لم تُثبَّت في بيئة
البناء هذه لأن سياسة الشبكة تمنع الوصول إلى `cdn.sheetjs.com`. الاستدعاء في الكود ديناميكي
(`await import('xlsx')`) فالترقية بديل مباشر بلا أي تعديل على الكود.
